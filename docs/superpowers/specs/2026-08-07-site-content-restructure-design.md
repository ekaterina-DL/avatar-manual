# Дизайн: переупаковка сайта-мануала «Аватар» (более ёмкая подача)

Статус: утверждено пользователем 07.08.2026, готово к переходу в implementation-план.

## Зачем

Сайт технически собран и опубликован (`https://ekaterina-dl.github.io/avatar-manual/`), но
пользователь оценил текущую подачу как «слишком громоздкую»: голые ссылки на видео, большие
картинки, служебные разделы не по теме, примеры оторваны от текста, к которому относятся. Это —
именно то, что в `site/PLAN.md` изначально было названо «Phase 2» (карточки-факты, значки,
сетка примеров с zoom) плюс несколько новых конкретных правок, обнаруженных в этом заходе.

**Жёсткое ограничение (не меняется с прошлой сессии):** файлы `manual-2-etap/*.md` и
`manual-3-etap/*.md` не редактируются ни на байт. Все изменения — только на уровне сборки сайта
(файлы в `site/`, в первую очередь build-хуки MkDocs).

## Объём этого захода

Не «причесать всё разом», а начать с страниц, где преобразование даёт максимальный эффект и
минимальный риск, посмотреть вживую на реальном сайте, и только потом решать, катить ли на
остальные разделы (04-common-mistakes, FAQ, disputed-points, qa-log — сознательно вне объёма
сейчас, там другой паттерн подачи).

Целевые страницы для точечной (не только глобальной) переделки:
- `manual-2-etap/00-overview.md`, `manual-3-etap/00-overview.md` — только удаление 2 разделов.
- `manual-2-etap/02-segments.md` — полная переделка (1-в-1 совпадает с уже утверждённым макетом).
- `manual-2-etap/03-video-quality.md` — упаковка уже существующих рядом лежащих примеров.
- `manual-2-etap/04-classifier.md` — точечные превью примеров у части полей.
- `manual-3-etap/04-video-quality.md` — точечные превью примеров (аналог для 3 этапа).
- `manual-3-etap/07-example-library.md`, `manual-2-etap/11-example-library.md` — не
  переструктурируются, но автоматически получают визуальные улучшения (картинки/видео) как и
  весь остальной сайт.

Все технические механизмы ниже (хуки) применяются глобально по всему сайту — если на другой
странице случайно встретится тот же паттерн (список ссылок на видео, таблица
Правильно/Неправильно с картинками), он тоже автоматически станет компактным. Это не противоречит
«постранично» — просто дополнительный бонус без лишней работы.

## Механизм 1 — быстрые правки по всему сайту

### 1a. Удаление разделов, не нужных на сайте

Новый хук `site/hooks/hide_site_only_sections.py`. Список конкретных пар (файл, точный текст
заголовка) — никакого нечёткого сопоставления:

| Файл | Заголовок | Где заканчивается |
|---|---|---|
| `manual-2-etap/00-overview.md` | `## История проекта: этапы во времени` | перед `## Порог качества по ходу работы...` |
| `manual-2-etap/00-overview.md` | `## Как читать этот мануал` | конец файла |
| `manual-3-etap/00-overview.md` | `## История проекта во времени` | перед `## Нормативы` |
| `manual-3-etap/00-overview.md` | `## Как читать этот мануал` | конец файла |

Хук вырезает markdown-текст от заголовка (включительно) до следующего заголовка того же или
более высокого уровня (`##`/`#`), исключительно на этапе сборки сайта.

### 1b. Картинки — маленькие, увеличиваются по наведению

Правка `site/theme/extra.css`: все `<img>` внутри текста статьи получают вид маленькой карточки
(фиксированная ширина, скруглённые углы, тень) и увеличиваются при наведении курсора — это уже
готовый, утверждённый на макете CSS (`.example-card:hover img` / `.compare-card:hover img` из
`site/prototype-reference/template.html`), переносим как есть.

**Исключение — крупные интерфейсные/справочные изображения остаются в текущем размере**
(явный список имён файлов, не эвристика):
- `interface-overview.jpeg`
- `classifier-panel-fields.png`
- `classifier-single-checkboxes.png`
- `classifier-multi-checkboxes.png`
- `trim-buttons.png`
- `anthropomorph-calibration-chart.png` (в обоих мануалах — плотная калибровочная таблица
  заказчика с мелкими деталями, не одиночный пример)

Реализация — по имени файла в `src` картинки (CSS-селектор по концу пути или отдельный список
классов, проставляемых build-хуком).

### 1c. Ссылки на vkvideo.ru → встроенный плеер

Сейчас единственное место с «голыми» ссылками на видео вместо плеера — `manual-2-etap/02-segments.md`
(10 ссылок вида `https://vkvideo.ru/video712360465_456239217`, у одной есть `?list=...`).

Новый хук `site/hooks/embed_vk_video.py` (тот же принцип, что уже работает в
`embed_local_media.py` для `.mp4`): по регулярке вида
`https?://vkvideo\.ru/video(-?\d+)_(\d+)` достаёт `oid` (может быть отрицательным — паблик) и
`id`, вставляет вместо ссылки:

```html
<iframe src="https://vk.com/video_ext.php?oid={oid}&id={id}&hd=2"
        loading="lazy" allowfullscreen></iframe>
```

Технически проверено (07.08.2026): `video_ext.php` отдаёт рабочую страницу-плеер (HTTP 200) без
пароля/хеша для этих публичных видео. `loading="lazy"` — чтобы iframe не грузился, пока не
попадёт в область видимости (нативная возможность браузера, без JS).

## Механизм 2 — автоматическая упаковка уже существующих рядом лежащих примеров

Там, где в тексте **уже сейчас** подряд идут примеры (это часть контента, а не что-то
добавляемое) — визуально это сплошной список больших `<video>`/`<img>`, из-за чего выглядит
громоздко. Упаковываем в сетку карточек, содержание не меняется.

### 2a. Список ссылок на видео подряд под заголовком → `.video-block` / `.video-item`

Новый хук `site/hooks/group_media_lists.py`, выполняется **после** `embed_local_media.py` и
`embed_vk_video.py` (то есть работает уже с готовыми `<video>`/`<iframe>`, а не с сырыми
ссылками). Находит подряд идущие пункты списка (2 и более), где каждый пункт содержит ровно один
встроенный `<video>` или `<iframe>`, и оборачивает всю группу в разметку `.video-block` >
`.video-grid` > `.video-item` (классы и вёрстка — из утверждённого макета). Подпись пункта
(текст после видео, если есть) становится подписью карточки (`.vi-cap`).

Затрагивает уже сейчас: `manual-2-etap/03-video-quality.md` (несколько таких списков — «Примеры
Битое», «Темп речи — примеры» и др.), `manual-3-etap/07-example-library.md` («Подходящие видео»,
«Антипримеры», каждый пункт «Топ-5 ошибок»). Одиночные примеры видео не в списке (просто
упомянутые в абзаце) не трогаем — группировать нечего, и так не громоздко.

### 2b. Блоки «Пример N» / «Антипример N» → `.example-grid` / `.example-card`

Только `manual-2-etap/02-segments.md` (5 примеров + 6 антипримеров, единственное место с таким
паттерном). Новый хук `site/hooks/build_segment_examples.py`, специфичный для структуры этой
страницы:

```
**Пример N:** https://vkvideo.ru/videoXXX_YYY
![alt](assets/exampleN-frame.jpeg)
Текст подписи (1-3 предложения, может быть жирная строка «Подходящий сегмент: ...»)
```

→ карточка `.example-card` с embed-плеером вместо статичного кадра (пользователь явно просил
именно «видео в плеере», а не картинку-кадр + ссылку рядом — два раза одно и то же не нужно),
номером и текстом подписи. Статичный jpeg-кадр в разметке карточки не используется (дублировал
бы то, что теперь показывает сам плеер).

### 2c. Таблица «Правильно / Неправильно» с картинками → `.compare` / `.compare-card`

Сейчас 1 известное место — `manual-2-etap/02-segments.md:110-113` (сравнение таймлайна,
`timeline-correct-spacing.png` / `timeline-incorrect-overlap.png`). Хук
`site/hooks/build_compare_cards.py` ищет двухколоночную markdown-таблицу с заголовками ровно
«Правильно» / «Неправильно», где в ячейках — картинки, и заменяет на `.compare-card.good` /
`.compare-card.bad` (зелёная/красная плашка `✓ Правильно` / `✗ Неправильно`, картинка с zoom,
подпись).

**Вне объёма сейчас:** таблица «Наглядно: один человек в кадре vs два и более» в
`manual-2-etap/04-classifier.md` — по форме похожа, но не про «правильно/неправильно» (это
демонстрация, а не сравнение верного и неверного), красно-зелёная раскраска была бы по смыслу
неверной. Оставляем как есть (существующая простая таблица), не пытаемся притянуть под тот же
компонент.

## Механизм 3 — точечные превью примеров у полей классификатора

Единственное место, где примеров рядом с текстом **пока нет вообще** (в отличие от механизма 2,
где они уже есть, просто криво отображаются) — страницы классификатора. Здесь нужна новая,
явно прописанная (не автоматическая) привязка «этот кусок текста → эти конкретные примеры из
банка», потому что автоматически понять соответствие поля и раздела банка невозможно.

Новый хук `site/hooks/inject_example_previews.py` с явной таблицей соответствий (site-only
конфиг, не трогает файлы мануала). Хук на этапе сборки читает **сырой markdown исходного файла**
банка примеров, вырезает нужный раздел, оставляет только первые 2-3 пункта (для наглядности, не
для исчерпывающего охвата), оборачивает как `.video-block`, и вставляет в текст целевой страницы
сразу после указанного якоря — плюс ссылку `→ ещё N примеров в банке` на полный раздел (тот же
раздел остаётся нетронутым и полным на странице банка).

**Таблица соответствий (2 этап, `04-classifier.md` ← `11-example-library.md`):**

| Куда (в тексте 04-classifier.md) | Откуда (раздел в 11-example-library.md) |
|---|---|
| Уточнение про «Темп речи» | `## Темп речи` (все 3 примера — короткий раздел, помещаются целиком) |
| Уточнение про «Эмоции — не злоупотреблять other» | `## Эмоции` (по 1 примеру из «Счастье»/«Нейтральная»/«Другое») |
| Уточнение про «Ракурс при активном вращении головой» | `## Ракурс` |
| Уточнения про «Диалог или монолог» / закадровый голос | `## Диалоги и закадровый голос` |

Сознательно **не** делаем превью для «Вид съёмки» — сам файл-источник прямо помечает этот раздел
как не подтверждённое поле 2 этапа (терминология 3 этапа), тащить его как иллюстрацию
официального поля было бы некорректно. Раздел «Тряска камеры vs плавное движение» тоже не
привязываем ни к одному полю классификатора — по смыслу это не про заполнение классификатора, а
про общее качество/брак, явного 1-в-1 попадания в этот файл нет.

**Таблица соответствий (3 этап, `04-video-quality.md` ← `07-example-library.md`):**

| Куда (в тексте 04-video-quality.md) | Откуда (раздел в 07-example-library.md) |
|---|---|
| `## Когда сразу «Битое»` | `## Примеры` → «Антипримеры» + Топ-5 п.1 «Размечено битое видео» |
| `## Когда отмечать «Артефакт»...` | Топ-5 п.2 «Наличие артефакта» |

У 3 этапа классификатор (`01-classifier.md`, 19 вопросов) с банком примеров по вопросам не
совпадает вообще (банк там — про качество видео целиком, не про конкретные вопросы), поэтому
превью для него не делаем — не с чем сопоставлять без выдумывания несуществующей привязки.

## Что сознательно не входит в этот заход

- `06-common-mistakes.md`, `07-faq.md`, `08-lifehacks.md`, `09-disputed-points.md`,
  `10-qa-log.md` (2 этап) и их аналоги на 3 этапе — другой паттерн подачи (разбор кейсов, а не
  примеры-иллюстрации), не подходят под уже готовые компоненты макета. Отдельный заход по
  желанию, после того как будет видно, как смотрится этот.
- Полное дублирование всего банка примеров (~230 ссылок) на страницы классификатора — решили
  явно не делать (раздувает страницы), см. ответ на вопрос про банк примеров.
- Адаптация под мобильный телефон — по-прежнему вне объёма (решено раньше, в `site/PLAN.md`).

## Порядок реализации и проверка

Все хуки — новые файлы в `site/hooks/`, подключаются в `mkdocs.yml` в списке `hooks:` (порядок
важен для механизма 2a — после хуков встраивания медиа). Ни один файл в `manual-2-etap/` или
`manual-3-etap/` не редактируется.

Проверка перед тем, как считать готовым:
1. `mkdocs build --strict` без ошибок (как и раньше).
2. Живой просмотр в браузере (не просто проверка сборки) — `02-segments.md` целиком, плюс по
   одному полю с превью на каждой из двух страниц классификатора/качества.
3. Проверить, что vkvideo.ru embed реально проигрывает видео в браузере (не просто HTTP 200 у
   `video_ext.php`, а фактическое воспроизведение).
4. Проверить, что раздел «История проекта»/«Как читать» не отображается на сайте, но при этом
   исходные `.md`-файлы не изменились (`git diff` по `manual-2-etap/`, `manual-3-etap/` — пусто).
