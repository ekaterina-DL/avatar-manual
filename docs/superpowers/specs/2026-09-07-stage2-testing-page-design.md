# Страница тестирования по 2 этапу

**Дата:** 2026-09-07
**Статус:** утверждено, реализуется

## Задача

Сделать для мануала 2 этапа отдельную страницу тестирования (самопроверка асессора). Требования
пользователя:

- Отдельный, визуально выделенный раздел в левом меню сайта.
- Вступление: «перед прохождением тестирования обязательно ознакомиться со всем мануалом по
  2 этапу».
- Поля ввода **Фамилия** и **Имя**; итоги каждого прохождения должны попадать в Google-таблицу:
  дата прохождения, фамилия, имя, результат, неверные ответы.
- **15 вопросов**, ограничение **60 секунд на вопрос**. Не успел — переход к следующему.
- После ответа: верно — сразу надпись «верно»; неверно — показывается правильный ответ.
- В конце: процент и количество верных ответов, плюс разделы мануала, которые нужно повторить
  по неверным ответам.
- Каждый тест уникален (не повторяется с предыдущим). 15 вопросов каждый раз собираются со
  всего актуального сайта-мануала, **кроме страницы «Обзор проекта»** (`00-overview.md`). Если
  контент мануала меняется — в тесте только актуальная информация.
- Должны быть вопросы с видео-примерами и вариантами ответов типа «на каком отрезке такой-то
  дефект» / «какой дефект на таком-то отрезке». Вариантов ответа — не менее 3, верный — один.

### Что решили на этапе обсуждения

- **Источник вопросов — гибрид:** Python-хук на сборке сайта извлекает пул вопросов из
  структурированных мест мануала 2 этапа + подмешивает небольшой ручной блок вопросов для
  правил, у которых нет машиночитаемой структуры. Видео-вопросы обновляются автоматически при
  правках мануала; понятийные правятся вручную (как и весь остальной контент сайта).
- **Доставка итогов — Google Apps Script (веб-приложение).** Сайт статический (GitHub Pages),
  своего бэкенда нет. Страница шлёт один POST на `/exec`-URL скрипта, скрипт дописывает строку
  в лист. URL публичный (виден в исходниках) — прикрываем лёгким токеном; для внутреннего
  обучающего теста этого достаточно.
- **Место в меню — отдельный top-level раздел** (сосед «2 этап»/«3 этап»), пункт выделен
  цветом-акцентом и иконкой через CSS.
- **После ответа — кнопка «Далее»** (асессор сам жмёт, прочитав разбор). Ограничение 60 сек —
  только на сам ответ, не на чтение разбора.
- **Итог теста — вердикт «Сдано / Не сдано»** по порогу (80% по умолчанию, меняется в конфиге)
  **+ разбивка по темам** (таблица «тема / промахов / ссылка на раздел»).
- **Видео и таймер:** видео встроено, автостарт без звука, зациклено, с контролами; плеер
  играет только оцениваемый сегмент (`#t=начало,конец`). Таймер стартует, **когда видео
  готово к проигрыванию** (для текстовых вопросов — сразу). **60 сек** на текстовый вопрос,
  **90 сек** на вопрос с видео (`QUESTION_SECONDS` / `VIDEO_QUESTION_SECONDS` в `quiz.js`).
- Видео-вопросы — это часть набора, не все 15. В тесте есть и текстовые вопросы про числа и
  правила.
- Черновик ручного блока пишу я из текущего текста мануала; пользователь проверяет.

`build_quiz_bank.py` ставится в списке `hooks:` **после** `embed_video_links.py` и

## Как собираются вопросы

Хук извлекает вопросы **только из мест, где правильный ответ явно задан в самом мануале.**
Ничего не «додумывается»: если правильный ответ нельзя однозначно вывести из разметки —
источник пропускается (или уходит в ручной блок).

### Источник A. Поля классификатора по видео (`04-classifier.md`)

Подписи под заголовками `### N. <Поле>` вида:

```
- [**Голова и плечи** — кисти рук не видны (78.4–95.9)](…mp4)
- [**Анфас** (0:06.48–0:18.06)](…mp4)
```

- Извлекается: имя поля (из `###`), правильное значение (жирный текст в начале подписи),
  примечание, тайм-код (если есть).
- **Защита:** берём подпись, только если жирный текст в начале **точно совпадает** с одним из
  значений `<ul class="value-checklist">` этого поля. Подписи без совпадения («Ракурс меняется
  в пределах ролика — берём преобладающее») для шаблона «что на видео» не используются.
- Шаблон вопроса: «Определите значение поля «**<Поле>**» для сегмента **M:SS–M:SS**.»
  Варианты = правильное значение + 2–3 других значения **из списка того же поля** (случайно).
  Раздел для повторения = якорь этого `###` в «Классификаторе».
- **Говорим про сегмент, не про «видео», и указываем какой** (просьба заказчика после
  тестирования). Классификатор заполняется по одному сегменту, а в одном видео сегментов
  может быть несколько — с разными полями, — поэтому без отрезка вопрос неоднозначен.
  `_parse_timerange` берёт из подписи начало и конец:
  - `(78.4–95.9)`, `(0:06.48–0:18.06)`, `(0–86.3)`, `(до 0:53)` → «…для сегмента M:SS–M:SS»;
    плеер стартует и (с `loop`, в Chrome) крутится в этом окне — `#t=начало,конец`, поля
    `videoStart` / `videoEnd`;
  - обрезанный ролик (`/trimmed/…__segment_…`) — уже один сегмент целиком → «…для этого
    сегмента (ролик целиком, M:SS)»; длина берётся из имени файла
    (`__segment_<n>_<нач>_<кон>`), чтобы исполнитель видел, что ролик длинный;
  - полный видео-источник **без** тайм-кода в подписи → вопрос не собирается (нельзя честно
    указать, какой отрезок оценивать).
  Для «Битого» (источники B и C-антипримеры) тайм-код не нужен — бракуется всё видео целиком.
- Хорошее покрытие примерами: «Объём и поза тела», «Преобладающий ракурс», «Освещение», «Фон».
  Прочие поля (пол, возраст, эмоции, тип речи, темп, язык, группа данных) примеров почти не
  имеют — их закрывает ручной блок.

### Источник B. «Битое» / исключённые типы

Два подисточника с **разной надёжностью**:

1. **`11-example-library.md`, раздел «Битое — примеры дефектов»** — надёжный. Подписи сами по
   себе описывают дефект («Смена кадра в конце», «Кашель перебивает говорящего», «Звук ветра
   слишком громкий»). Шаблон: «Какой дефект в этом видео?» / «Почему видео уходит в „Битое“?».
   Варианты = подпись этого пункта, нормализованная до короткой формулировки, + подписи других
   пунктов того же списка.
2. **`05b-what-not-to-label.md`, подразделы «Дефекты, которых не должно быть в сегменте»** (Склейки,
   Рамка, Пиксельность, Тряска камеры, Пережатие, Виньетка, Монтажное наложение, Дубляж,
   Синхронизация, Смена кадра/сцены) — **осторожно.** Списки «Калибровочные примеры» под этими
   подразделами содержат и контрпримеры: «Нет пиксельности, для сравнения», «Некритичная
   пиксельность (из-за освещения)», «реальная, подтверждённая рамка, брак не оспаривается».
   Правила:
   - берём пункт, только если подпись **не содержит** маркеров отрицания/смягчения: «нет»,
     «некритичн», «для сравнения», «допустим», «не всегда», «баг плеера»;
   - тема вопроса = заголовок подраздела (это и есть категория дефекта);
   - шаблон: «Что не так с этим видео (почему в „Битое“)?». Варианты = заголовок этого
     подраздела + заголовки соседних подразделов.
   - Если после фильтра в подразделе не осталось пунктов — подраздел не даёт вопросов.

### Источник C. Позитив / антипримеры (`05-what-to-label.md`)

Блоки `**Пример N:** <iframe>…` и `**Антипример N:** <iframe>…` (их уже разбирает
`build_segment_examples.py`; переиспользуем ту же логику извлечения).

- Шаблон: «Это видео — подходящий сегмент или его нужно отправить в „Битое“?». Ровно
  **2 варианта**: «Подходит для разметки» / «В „Битое“».
- Пример (в т.ч. многосегментный) → правильный «Подходит»; Антипример → «В „Битое“».
  Вариант «Нужно поделить на N сегментов» убран (2026-09-08): вопрос бинарный, а
  комментарий мануала к «Примеру» относится к сегменту внутри видео, не к видео целиком.
- Раздел для повторения — «Что размечаем» / «Что не размечаем».

### Источник D. Числа и правила из разметки

Из `<div class="keyfacts">`, `<ul class="value-checklist">`, устойчивых жирных формул:

- длительность сегмента 10–300 сек; максимум 10 сегментов на видео; максимум длины видео 10:15;
  порог экзамена ≥80%; порог текущего качества 85%; 13 полей классификатора; «один человек →
  один ответ»; множественный выбор — только при 2+ людях в кадре.
- Шаблон: текстовый вопрос с числовыми/списочными вариантами («Максимальная длительность
  одного сегмента?» → 60 / 120 / 300 / 600 сек). Неверные варианты — правдоподобные соседние
  числа.
- Раздел для повторения — соответствующая страница/заголовок.

### Источник E. Запрещённое в сегменте (`02-segments.md`, список `kf-tag`)

Теги «смену кадра, склейки, рамки, водяные знаки, наложенный текст, дубляж, ИИ-изображения,
нейро-аватары, виньетку, субтитры, тряску камеры, большую пиксельность, пережатие, закадровый
голос, молчание > 4 сек».

- Шаблон: «Что из перечисленного не должно попасть в сегмент?» — верный вариант из списка тегов,
  неверные — правдоподобные «допустимые» вещи (пиксельность на фоне, лёгкий фоновый шум, окно
  в кадре, поворот головы).
- Раздел — «Сегменты».

### Источник F. Ручной блок (`_quiz-manual.yml`)

~15–25 вопросов для правил без машинной структуры. Формат одного вопроса:

```yaml
- id: seg-boundary-speech
  topic: Границы сегмента
  question: С чего должен начинаться и чем заканчиваться сегмент?
  video: https://…            # опционально
  video_start: 12.5           # опционально, секунды
  options:
    - Ровно с начала и до конца речи человека   # верный — первый в списке
    - С любого удобного места длительностью 10 сек
    - За 3–4 кадра до начала речи
  answer: 0
  review:
    title: Сегменты
    url: 02-segments.md#определение-и-границы
```

Темы для ручного блока (черновик из текущего мануала): границы сегмента ровно по речи; отступ
от склейки 3–4 кадра; когда делить/объединять сегмент; «поддакивание = диалог»; эмоция по тону
голоса, а не по мимике; преобладающий язык (мимолётное вкрапление не считается); «считаем
только того, кого снимает камера»; «сегмент + „Битое“ одновременно нельзя»; резкий зум — не
берём, плавный — берём; shorts сам по себе не брак.

### Формат заготовки в банке (`<script id="quiz-bank">`)

```json
{
  "generatedAt": "2026-09-07T…",
  "questions": [
    {
      "id": "clf-rakurs-<hash>",
      "source": "A",
      "topic": "Преобладающий ракурс",
      "question": "Определите значение поля «Преобладающий ракурс» для сегмента 0:06–0:18.",
      "video": "https://…mp4",
      "videoStart": 6.48,
      "videoEnd": 18.06,
      "options": ["Анфас", "Полуоборот (3/4)", "Профиль"],
      "answer": 0,
      "review": { "title": "Классификатор", "url": "04-classifier.md#4-преобладающий-ракурс" }
    }
  ]
}
```

- `id` — стабильный хэш от источника (страница + якорь + URL видео + тип шаблона), чтобы
  `localStorage` мог исключать вопросы прошлой попытки.
- `options` в банке хранятся в «каноническом» порядке (верный первым, `answer` всегда
  указывает на него); JS перемешивает варианты при показе.
- Неверные варианты (дистракторы) для источников A/B/E частично фиксируются на сборке, но JS
  при каждом заходе может доизбирать/переставлять их из пула значений темы — это усиливает
  «непохожесть» повторно выпавшего вопроса.

## Поток и экраны (quiz.js)

1. **Старт.** Вступление (markdown уже на странице), краткий блок «как устроено» (15 вопросов;
   60 сек на вопрос; не успел — переход дальше; после ответа — разбор и кнопка «Далее»; в конце
   — % и разделы для повторения). Поля **Фамилия**, **Имя** — обязательны; кнопка «Начать тест»
   неактивна, пока оба поля пусты (обрезаем пробелы). ФИО храним в памяти на время попытки.
2. **Сборка набора.** Из банка выбираются 15 вопросов (см. «Уникальность и распределение»).
3. **Вопрос (×15).** Карточка: номер «Вопрос N / 15», текст, встроенное видео (если есть;
   `autoplay muted loop playsinline controls`, старт с `videoStart`), 3–4 варианта (radio,
   один выбор). Круговой таймер 60 сек: стартует по событию готовности видео
   (`loadeddata` / `canplay`), для текстовых — сразу при рендере; на последних 10 сек —
   красный.
4. **Ответ / таймаут.** Клик по варианту фиксирует ответ, таймер стоп. Верно → зелёная плашка
   «Верно». Неверно / не успел → красная плашка «Неверно», подсвечен правильный вариант;
   таймаут без ответа = неверный (в отчёте выбор = «— (не успел)»). Внизу — кнопка **«Далее»**.
5. **Результат.** Процент; «верных N из 15»; **вердикт «Сдано» / «Не сдано»** по
   `passPercent`; **разбивка по темам** — таблица «тема | промахов | ссылка на раздел»;
   плоский уникальный список разделов для повторения (с якорями). Кнопка «Пройти заново».
6. **Отправка** — см. ниже; статус отправки показывается на экране результата.

## Отправка итогов в Google-таблицу

- `quiz.js` при завершении шлёт **один** `POST` на `QUIZ_CONFIG.endpoint`:
  - `Content-Type: text/plain;charset=utf-8`, тело — строка JSON (так браузер не делает
    CORS-preflight, который Apps Script обрабатывает нестабильно);
  - режим «отправил и забыл» (`keepalive: true`); ответ не читаем.
- Поля payload: `token`, `startedAt`, `finishedAt`, `durationSec`, `surname`, `name`,
  `percent`, `correct` (N из 15), `verdict`, `wrongAnswers` (массив
  `{ n, question, chosen, correct, topic, reviewUrl }`), `questionIds` (для аудита),
  `userAgent`.
- Apps Script (`doPost`): проверяет `token`; формирует строку листа —
  `дата/время` (ставит сам, `new Date()`), `фамилия`, `имя`, `процент`, `верных из 15`,
  `вердикт`, `неверные ответы` одной ячейкой (по строке на промах:
  «N. <вопрос> — выбрано: <chosen> — верно: <correct> — раздел: <reviewUrl>»),
  `длительность`, `id вопросов`. `appendRow` в целевой лист.
- **Инструкция публикации** (отдельный файл): создать Google-таблицу → Расширения → Apps
  Script → вставить код → задать `TOKEN` → Развернуть → Веб-приложение → «Выполнять от моего
  имени», «Доступ: все, у кого есть ссылка» → скопировать URL `…/exec` → прислать; вставляю в
  `quiz-config.js`, тот же `TOKEN` — в оба места.
- **Фолбэк:** если `fetch` бросил/недоступен — на экране результата показываем
  «Не удалось отправить результат автоматически — сделайте скриншот этого экрана и пришлите
  куратору». Экран результата при этом полностью самодостаточен (все цифры и разделы видны).

## Уникальность и распределение

- **Пул:** оценочно 80–120 авто-вопросов (зависит от того, сколько подходящих примеров сейчас
  в мануале) + ручной блок. Реальное число печатает хук в лог сборки.
- **«Не повторяется с предыдущим»:** `localStorage` хранит `questionIds` последней **завершённой**
  попытки на этом устройстве. Следующий набор их исключает. Если исключение оголяет тему (не
  набирается нужное число в корзине) — ограничение по этой теме мягко ослабляется. Порядок
  вариантов и часть дистракторов пересобираются при каждом заходе, поэтому даже повторно
  выпавший вопрос выглядит иначе.
- **Распределение одного набора (ориентир):** ~5 «поле по видео» (A), ~3 «битое/дефект» (B),
  ~2 «подходит/не подходит» (C), ~2 числа/правила (D+E), ~3 из ручного блока (F). Взвешенный
  случайный выбор с потолком на тему (чтобы не было «15 вопросов про ракурс»); добор из
  остатка пула, если корзина мала. **Гарантия:** минимум 1 вопрос с каждой значимой страницы
  мануала — иначе «разделы для повторения» теряют смысл.
- **Актуальность:** банк пересобирается на каждой сборке из текущих `.md`. Убрали пример или
  правило из мануала — оно исчезает и из теста. `00-overview.md` в источники не входит
  (список целевых файлов в хуке — явный, без него).
