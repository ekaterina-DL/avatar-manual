Документ фиксирует всё, что уже обсудили и утвердили по визуалу и структуре, и порядок
технической сборки. Цель — свериться перед стартом, а не начинать переделывать на ходу.
Этот файл — источник истины по проекту сайта; если начинаете новую сессию Claude Code,
достаточно указать на него, полная история переписки не нужна.

полноценный пошаговый план с задачами, командами и проверками, уже опирающийся на этот файл:

папке сессии и рисковало потеряться — уже была найдена и исправлена одна реальная нестыковка:
детальный план угадывал акцентный цвет (`#C9852B`) вместо настоящего утверждённого (`#B96A22`).

**Два уточнения из того плана, которых не было здесь:**
- Файл `voprosy-zakazchiku.md` (внутренние вопросы к заказчику) — тоже не попадает в git/сайт,
  наравне с `_raw-sources/` и `_sources-log.md`.
- В `manual-2-etap/10-qa-log.md` найден и должен быть снят BOM (невидимый служебный символ в

**Одна вещь по-разному описана в двух файлах — это нормально, не ошибка:** детальный план

вслепую по всем страницам сразу. Общий визуальный язык (шрифты, цвета, скрытие источников,
подсветка «правильно/неправильно») входит в первую сборку.

## 1. Что уже решено

### Формат
Статический сайт (все страницы генерируются заранее в обычные html-файлы, без сервера и
базы данных) на основе **MkDocs Material** — готового бесплатного «движка» для документации,
с встроенным поиском, боковым меню и светлой/тёмной темой. Источник контента — те же
markdown-файлы мануала, что уже существуют.

### Разделение мануала и сайта
```
Data-Light. Обучение 2 этап/
├── manual-2-etap/     ← без изменений, как сейчас
├── manual-3-etap/     ← без изменений, как сейчас
├── _raw-sources/      ← без изменений, в сайт не попадает
├── README.md
└── site/              ← всё, что относится только к сайту
    ├── mkdocs.yml      конфиг: меню, тема, плагины
    ├── home/index.md   домашняя страница («выберите этап») — сайтовая, не часть мануала
    ├── theme/          цвета, шрифты, ховер-зум, карточки — из утверждённого макета
    ├── pdf/            настройки PDF-экспорта
    └── build/          готовый собранный сайт (создаётся заново при каждой сборке)
```
Документы мануала не знают о существовании сайта и не меняются под его нужды — их можно
свободно забрать в другой проект (например, для генерации тестов).

### Визуальный дизайн (утверждён на живом макете)
- Шрифты: **Golos Text** (заголовки, интерфейс, значки) + **PT Serif** (основной текст).
- Цвета: тёплый янтарный акцент; нейтральные холодные серые; отдельно зелёный/красный —
  только для смысловой пары «допустимо / недопустимо».
- Компоненты: карточки-факты для ключевых цифр (например, «10–300 сек»); значки по смыслу
  вместо точек в списках (время / запрет); сетка примеров по 3–4 в ряд с увеличением по
  наведению; видео-плееры встроены прямо в текст, не ссылкой; сравнение «правильно/неправильно»
  бок о бок.
- Метки-источники (`[Инстр., стр.2]`) — видны в PDF, скрыты на сайте (текст один, показ разный).
- Вёрстка рассчитана на десктоп, без ужатия под телефон (все читают с компьютера).

### Видео и картинки
- Прямые ссылки на sbercloud (859 шт.) — встраиваются по внешней ссылке напрямую, без скачивания.
- Ролики, требующие логина/капчи, — скачаны вручную в `assets/` каждого мануала и встраиваются
  как локальные файлы. Уже готово: 12 из Tagme (мануал 3 этапа) + 2 из Яндекс.Диска (мануал
  2 этапа: `training-2etap-layfhak.mp4`, `example-speech-overlay.mp4`).
- 3 длинных обучающих видео (не короткие калибровочные примеры) остаются кликабельными ссылками,
  не встраиваются плеером — их автоматически распознаёт хук по префиксу имени файла `training-`.

### PDF-версия
Отдельная, самостоятельно полезная вещь — собирается из тех же markdown-файлов (текст не
дублируется и не ведётся дважды), с видимыми источниками.

### Доступ и хостинг
Закрытая команда, специальная защита не критична — сайт может быть доступен по прямой ссылке,
без индексации поисковиками и без пароля. Пароль можно будет добавить позже, если понадобится.

**Решено:** публичный репозиторий на GitHub (аккаунт уже есть), публикация через бесплатный
GitHub Pages. `_raw-sources/` и служебные логи-журналы источников (`_sources-log.md` в каждом
мануале) в git **не попадают** — исключаются через `.gitignore` при инициализации репозитория.

### Правки
Мелкие правки текста — вы сами, в любом текстовом/markdown-редакторе; крупные изменения
структуры/дизайна — через меня.

## 2. Открытые вопросы

Обе закрыты — блокеров для старта сборки нет:
- **Адрес сайта** — решено: технический `имя.github.io/avatar-manual`, отдельный домен не нужен.
- **Кто ещё редактирует файлы** — решено отложить, вернёмся к этому после того, как сайт будет
  собран.

Порядок технической сборки — по шагам, с командами и проверками — см. в детальном плане,
на который ссылка в начале файла.

## 3. Что сознательно отложено

- Адаптация под мобильный телефон — не нужна, все читают с компьютера.
- Скачивание оставшихся 3 длинных обучающих видео — по желанию, сборку не блокирует.
- Пароль/логин на сайт — можно добавить позже, если понадобится.
- Карточки-факты, значки по смыслу, сетка примеров с zoom — Phase 2 детального плана, после
  публикации, постранично по живому сайту.
